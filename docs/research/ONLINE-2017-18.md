# Online messages of 2017–18: ghosts, rankings, saves (N0, 2026-10-14)

Research for ROADMAP "Online between shops", step N0. Sources: the decrypted originals
`control_Release.exe` (Hex-Rays dump `<runtime>\ida\control.c`) and `client_Release.exe` (IDA copy
`<runtime>\ida-gamesvr2\client_Release.exe.i64`), read only. Nothing was launched. [V] = seen in code,
[A] = assumed. Addresses: `sub_` = client unless marked "control".

## Conclusions

1. **Play between shops is asynchronous: ghost teams.** No message from the game server carries an address,
   port or session for another cabinet. The client asks for an opponent (GHOST_MATCHING), then for that
   opponent's saved team (GHOST_TEAM) or for an area's best eleven (BEST_ELEVEN), stores the team, and asks
   its own control for a match (`REQ_MATCH`, sub_4BC150). The shop's own match engine plays it. A hub only
   has to hold teams and answer three requests; it needs no real-time link and no latency budget. [V]
2. **Live play exists only inside one shop.** The control pairs its own satellites (`wccf::Matching::entry`,
   control ~0x4782xx: "p2p entry (sate%d,%s,%d)" with the seat's IP and port), and the two clients then talk
   peer to peer (`ClClientInterface`: ping, `TIMEOUT_P2P`, `P2P_DISCON`, `OPPONENT_VERSION_DIFF`, client
   options `CLIENT_PORT1..3`, `P2P_MATCHING_TEST`). The control only knows the seats of its own shop. [V]
   The one server-side matching message, `SLS_SVR_MATCH` (sender sub_4B8540), has **no callers**: dead code. [V]
3. **No "World Trophy" network mode in 2017–18.** The network mode select (`ADV_NetModeSelect` scenes) offers
   CHALLENGE_TOUR, GRAND_TROPHY (with playoff), LEAGUE, TOURNAMENT, VERSUS / VERSUS_UC and
   UNIVERSAL CHAMPIONSHIP (area select `AreaSelect_UT`). The server-ranked tournaments are **Grand Trophy**
   (GT: weekly id, classes, points, playoff, `SERVER_COACH_GT_*`) and **Union Trophy / Universal
   Championship** (UT: area, shop and association rankings, `SERVER_COACH_UT_*`, `RNK_UnionTrophy_*`).
   World Trophy survives as save fields (`CLUB_WT_POINT`, `CLUB_WT_SUCCESSION_CHAMPION_NUM`,
   `COACH_WT_RANKING_*`, `CLUB_WT_RANKING_ENTRYFLAG`), after-game screens (`AGM_WorldTrophyPoint_*`,
   `GAM_WT_result`) and a ceremony (`537_CUP_Ceremony_Rank_WorldTrophy`). The tournament state lives on the
   server: in the save data (SAVE_DATA / SAVE_DATA_SET) and in the GMSVR_RANK answer. [V for strings; the
   WT-to-GT succession is A]
4. **Every gmsvr message is relayed by the control.** The client writes a named variable to its control link
   (vtable +4 send, +8 receive, `sub_4ADAC0(name)` = still waiting); the control (`sub_443510`, control)
   fills slot, shop id and revision 47565, sends it to the game server (TCP 20050, 40-byte header,
   `gamesvr.rs`), and copies the answer back by slot (`sub_444CC0`, control). Clients poll 150 times (about
   2.5 s) before they give up. [V]
5. **Zero answers are not all safe.** GHOST_MATCHING with zeros reads as "no opponent" and the game falls back
   to a CPU team (fine). BEST_ELEVEN and GHOST_TEAM with errCode 0 are taken as a valid team and an all-zero
   team is installed (sub_847DF0, sub_7FBB90). The stand-in should answer those two with errCode ≠ 0 until it
   holds real teams. [V for the branch; the effect of an empty team on the match is A]

## Common rules

| Rule | Detail |
|---|---|
| Request +0 | u32: client puts its satellite number (`dword_15DD9B4`); control overwrites with its slot index [V] |
| Shop id | client: `sub_4D27A0` = ALL.Net shop id parsed as hex (0 without ALL.Net); control overwrites with its own shop id (`this+74`) [V] |
| Revision | u32 47565 next to the shop id in every request [V] |
| Answer +0 | slot; the control matches answers to seats by it (stand-in echoes it) [V] |
| Answer +4 | errCode, 0 = success, for every message below [V] |
| Header status | the control uses the payload only if header status > 0 (stand-in sends 1) [V, RESEARCH.md] |

## GHOST_MATCHING 305 → 306

Sender sub_4BBEA0, called from sub_7FBA00 (match type 34, play modes 1 and 7, object `dword_6D9F244`) and
sub_836220 (match type 33, play mode 6, object `dword_6D9F278`), both from the pre-match sequence sub_69F870
(state 0). Receivers sub_7FBA50 / sub_836270. Control relay: request case 305 (`sub_40A4F0`), answer case 306
logs up to 8 entries.

Request, 24 bytes:

| Off | Size | Type | Meaning | |
|---|---|---|---|---|
| 0 | 4 | u32 | satellite / slot | V |
| 4 | 4 | s32 | matchingParameter = own team strength (sub_80C2F0: average player rating × 16 plus bonuses; 1360 base) | V |
| 8 | 2 | u16 | teamNum wanted, ≤ 8 (client sends 1) | V |
| 10 | 2 | u16 | match type (33 or 34; the same id the match setup sub_411E30 uses) | V |
| 12 | 2 | u16 | 0 | V |
| 14 | 1 | u8 | ALL.Net value from sub_C7A6A0 (field +2164 of the alw state; region) | V field, A meaning |
| 15 | 1 | u8 | 0 | V |
| 16 | 4 | u32 | shop id | V |
| 20 | 4 | u32 | 47565 | V |

Answer, 1,004 bytes:

| Off | Size | Type | Meaning | |
|---|---|---|---|---|
| 0 | 4 | u32 | slot | V |
| 4 | 4 | s32 | errCode | V |
| 8 | 4 | s32 | teamNum (entries filled) | V |
| 12 + 124·i | 124 | entry ×8 | ghost entry i | V |

Ghost entry (124 bytes, shared with GHOST_TEAM):

| Off | Size | Type | Meaning | |
|---|---|---|---|---|
| 0 | 4 | u32 | ghost id (non-zero = present); the GHOST_TEAM key | V |
| 4 | 56 | char[] | team name | V string, A which name |
| 60 | 56 | char[] | coach name | V string, A which name |

Use: if errCode = 0 and teamNum > 0 the client copies **entry 0 only** (124 bytes) into its object (+6916 /
+108) and sets "ghost found"; otherwise it clears the flag. Timeout (150 polls) gives the same result as no
ghost. Zero answer: no ghost, GHOST_TEAM is not sent, the match uses a CPU opponent. [V]

## What the hub must answer

1. **GHOST_MATCHING** (305/306): pick up to 8 stored teams near `matchingParameter`, same match type; fill
   errCode 0, teamNum, entries. teamNum 0 = no opponent (safe default).
2. **GHOST_TEAM** (307/308): return the team for a ghost id; errCode ≠ 0 when unknown (never zeros).
3. **BEST_ELEVEN** (311/312): an area's best team; errCode ≠ 0 when none (the zero answer is unsafe today).
4. **GMSVR_RANK** (249/250): rank, weekly and tournament results, prizes; tokens empty. Zeros are safe.
5. **SAVE_DATA_SET** (277/278): accept the match report, update the club and rankings, grant cards.
6. **SAVE_DATA** (275/276) and **COACH_LIST** (271/272): the club store (a shop server can answer these
   locally and sync to the hub).
7. **NEXT_MISSION** (317/318): mission data; zeros are accepted.
8. Not for the hub: BINARY_DATA (crash dumps, answer errCode 0 locally), SLS_* (logs, drop),
   GMSVR_ECHO (keep-alive, answer locally).
